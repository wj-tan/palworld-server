free-tier math

Sized to fill the allowance, then stop.

Always Free gives you 1,500 OCPU-hours and 9,000 GB-hours of Ampere A1 per month. A single instance at 2 OCPU / 12 GB, running continuously, consumes almost exactly that - which is why the default config is 2 OCPU / 12 GB and nothing more.

A1 compute 0 / 1,500 OCPU-hrs 99.2%
A1 memory 0 / 9,000 GB-hrs 99.2%
Block storage 0 / 200 GB boot volume 25.0%
Object Storage <0.1 of 20 GB Outbound transfer 10 TB/mo included VCNs 1 of 2

Figures are for a 31-day month, the worst case. Palworld ships x86-only binaries, so on Ampere the server runs under box64 emulation: a slow first boot in exchange for free hardware. Setting ARCH=x86 switches to a native AMD shape, which is paid - the scripts say so before they launch it.

what you get

Every part of the setup is a script you can read.

No console clicking, no Terraform state to babysit. Each stage is a short bash script driven by one config.env, and each one is safe to re-run.

One-command network

Creates the VCN, internet gateway, route table, security list and subnet, and opens the game ports at both layers - OCI security list and the instance's own iptables.

scripts/01-network.sh

Self-deploying instance

cloud-init waits out the boot-time apt lock, installs Docker, and brings up palworld-server-docker on first boot. Nothing to configure over SSH.

scripts/02-launch.sh

Capacity retry

Free ARM capacity comes and goes. The launcher backs off through "Out of host capacity" and 429 throttling until a host frees up, instead of failing at you.

out of host capacity → retry

Off-site backups

Compressed saves pushed to Object Storage every six hours through a write-only pre-authenticated request, so no credentials ever sit on the box. Auto-expiring.

scripts/03-backup-setup.sh

Save import

Move an existing world onto the server. Flushes the live world with RCON, backs up, swaps the files in, waits for healthy, and prints the exact rollback command.

scripts/import-save.sh save.zip

Always-Free guardrail

A compartment quota that hard-caps the whole tenancy to free-tier allowances, so a stray retry loop or a wrong shape simply cannot provision paid compute.

scripts/04-quota-guardrail.sh
quick start

Five commands, in this order.

You need an OCI account (Pay-As-You-Go greatly improves free ARM capacity - an idle 2 OCPU / 12 GB A1 instance stays free), the OCI CLI configured with an API key, an SSH keypair, and bash. Order matters for step 02: cap the tenancy before anything can launch.

01

Configure

Copy the example config and edit your region, server name, player cap and passwords. This one file drives every other script. It is gitignored, because it holds secrets.

$ cp config.env.example config.env
02

Cap the tenancy first

Applies the always-free-guardrail quota policy. Do this before you provision anything, so the ceiling is already in place when you launch.

$ scripts/04-quota-guardrail.sh
03

Create the network

VCN, subnet, internet gateway and the security list rules for UDP 8211, UDP 27015 and SSH.

$ scripts/01-network.sh
04

Launch

Launches the instance and hands it the cloud-init template. It installs Docker and starts Palworld by itself; under box64 the first SteamCMD download takes a while, and the container reports unhealthy until it finishes. That is expected.

$ scripts/02-launch.sh
$ scripts/manage.sh logs   # watch it come up
05

Off-site backups (optional)

Creates the bucket and a write-only PAR, and installs the cron that ships compressed saves every six hours. The PAR expires after a year - re-run to rotate it.

$ scripts/03-backup-setup.sh

Then join with direct connect to <PUBLIC_IP>:8211, using the password from your config if you set one. The public IP is ephemeral - scripts/manage.sh ip re-fetches it after a stop/start.

Loading an existing world

$ scripts/import-save.sh converted-save.zip
  • Takes a .zip, .tar.gz or directory, and finds the save root by locating Level.sav.
  • Installs into the world folder the server already loads, so world ID, settings and the backup cron keep working.
  • Skips WorldOption.sav by default, because it would silently override the game settings from your config.
  • Writes a local rollback tarball and prints the command to undo it.

Updating to a new build

$ scripts/update-server.sh
  • Takes a fresh off-site backup, pulls the latest image, and recreates the container so SteamCMD fetches the new build.
  • The world lives on a separate volume, so it survives the update.
  • On ARM a verify step can stall mid-download under box64 - the script watches for it and nudges the container.
  • --no-wait starts the update and returns immediately.
cost safety

Upgrading to Pay-As-You-Go quietly removes your ceiling.

The free-trial service limits are what stop a trial account from spending money. Upgrade to Pay-As-You-Go - which you want to do, because it is what makes free ARM capacity actually available - and those limits are raised out of the way. Nothing then prevents an expensive deployment except your own care.

A budget alert only tells you afterwards. So this project ships a compartment quota that puts the ceiling back by policy: A1 capped at 2 OCPU and 12 GB, block storage at 200 GB, and every paid compute shape zeroed. It applies to new provisioning, so your running server is unaffected.

The repo's CLAUDE.md also instructs any AI assistant working in it to verify resources against Oracle's live Always Free documentation and to stop and ask before creating anything paid.
